## 作品概要(必須項目)

mdvはターミナル上で動作する**超軽量なMarkdownビューア**です。

起動は約**30ms**、メモリ使用量は約**8MB**、バイナリサイズは約**4MB**。
ブラウザ(100〜500MB)やIDE(200〜400MB)を使わずに、Markdownファイルを美しく閲覧できます。

主な機能:
- 見出し・コードブロック・テーブル・タスクリスト・引用・GitHub Alertsのリッチなレンダリング
- シンタックスハイライト(syntect / Sublime Text互換の6テーマ)
- ライブリロード(ファイルを保存すると即座に再描画)
- 目次ナビゲーション(`t`キーで開いて`Enter`でジャンプ)
- 6種類のコードテーマ + UIテーマ(dark/light)
- キーバインド一覧のヘルプ画面(`?`キー)
- Windows / macOS / Linux対応、SSH環境でも快適に動作

## 制作背景

「Markdownを確認したいだけなのに、毎回ブラウザやVSCodeを起動するのが面倒」
という日常的な不満が制作のきっかけです。

- ドキュメントを確認するたびにブラウザ(1〜3秒)やIDE(2〜5秒)の起動を待つ
- `cat`や`less`では見出し・テーブル・コードの構造が読めない
- SSH先のサーバーではブラウザやIDEが使えない

ターミナルでの作業を一切中断せず、**「見る」ことに特化した**軽量ビューアがあれば、
ドキュメント確認がストレスなくワークフローに溶け込むと考え、mdvを開発しました。

## システム構成

| 技術 | 用途 | 選定理由 |
|------|------|---------|
| Rust | コア実装 | メモリ安全性と高速性、シングルバイナリ |
| ratatui | TUIフレームワーク | リッチなターミナルUIを宣言的に構築 |
| pulldown-cmark | Markdownパーサー | CommonMark準拠の高速パーサー |
| syntect | シンタックスハイライト | Sublime Text互換テーマで高品質なハイライト |
| notify / notify-debouncer-full | ファイル監視 | クロスプラットフォーム対応 |
| tokio + crossterm | 非同期ランタイム / 端末制御 | キー入力とファイル監視を非同期で並行処理 |

## 実装内容

1. **パーサー層**: pulldown-cmarkのイベントストリームを、レンダリングに適した独自の
   構造化モデル(`ParsedLine`)に変換。見出し/コード/リスト(ネスト・タスクリスト)/
   テーブル/引用/GitHub Alertsをすべて構造化して保持する。
2. **レンダリング層**: Unicode文字幅を正しく扱うワードラップと罫線描画。
   日本語の全角文字を含むテーブルやコードブロックでもレイアウトが崩れない。
   見出しレベルごとに異なる装飾、アラートタイプごとの色分けで視認性を向上。
3. **非同期イベント処理**: `tokio::select!`でキーイベントとファイル変更イベントを
   並行処理。ライブリロードはデバウンス(100ms)で高頻度の保存にも対応。
4. **パフォーマンス最適化**: 起動時の遅延処理の排除、目次幅のキャッシュ化などにより
   100KBのMarkdownを約30msで表示。

## アピールポイント

### こだわった点: 数字で示す「軽さ」
- 起動 **約30ms**(ブラウザの1/100、VSCodeの1/100以下)
- メモリ使用量 **約8MB**(ブラウザの1/50以下)
- バイナリサイズ **約4MB**(strip・LTO適用のシングルバイナリ)
- `time`コマンドとメモリ計測で実測値を文書化し、ベンチマークもリポジトリに同梱

### 苦労した点
- **Unicode幅の問題**: 日本語(全角文字)を含むテーブルで列がズレる問題を、
  文字幅を考慮した自前のラップ処理と幅計算で解決
- **複雑なMarkdown構造**: ネストされたリストやタスクリストを正しい階層で表示する
  パーサーの状態管理に試行錯誤
- **リソースリーク対策**: ファイル監視タスクが終了時にリークしないよう、
  CancellationTokenによるキャンセルとチャネル送信のエラーチェックを実装
- **クロスプラットフォーム**: Linux/macOS/Windowsの3OSでCIを回し、
  ファイル監視のバックエンド差(NoCache/FileIdMap)によるビルド差異を解消

### 工夫した点
- SSHでリモートサーバーに接続したまま動作するため、GUI不要のターミナル完結設計
- ライブリロードにより、エディタで編集中のドキュメントをリアルタイムプレビュー
  (AIエージェントのMarkdown出力を眺める用途にも最適)
